# Hands-On: FreeRTOS with Live Variables

This hands-on exercise walks you through initializing a FreeRTOS application.

---

## ⚙️ STM32CubeMX2

1. Launch **STM32CubeMX2**, select **Start from MCU**, and search for the part number: `STM32C562RET6`.
2. Click **Automatically Download, Install & Create Project**.
3. Click **Launch Project**.
4. Locate the global search field in the **Pinout** view in the top-left corner (**Search for any text...**), then type `PA5`.
5. Observe that the tool automatically highlights pin `PA5`.
6. Right-click pin **PA5** ➞ **Assign signal** ➞ Check **GPIO**, then click the **Gear icon (Configure)**.
7. Configure the pin properties within the setup panel layout:
   * **SW Label for signal:** `LED1`
   * **Mode:** `Output`

### Configuring FreeRTOS & Resolving the SysTick Conflict
1. In the left peripheral menu, navigate to **Middlewares & Utilities ➞ FreeRTOS** and click on **Activate**.
2. ⚠️ **Warning:** Notice the configuration conflict warning shown. Because the FreeRTOS kernel uses the 'SysTick' timer to manage task scheduling and time slicing, it can no longer be used as HAL timebase.
3. To resolve this, open **Peripherals ➞ TIM6** and click **Activate**.
4. Now open **Project settings ➞ HAL common definitions ➞ Configure (gear symbol) ➞ HAL timebase selection**. 
5. Switch the selection from **SysTick** over to **Timer**, and explicitly assign **TIM6** from the drop-down menu.

### OS Task Setup & Generation
1. Navigate back to **FreeRTOS ➞ Applicative ➞ Tasks**.
2. Click **Add item to Tasks** to generate a custom thread entry slot. 
You can leave the parameters at their default values.
3. Move to **Project settings** and verify that your toolchain output **Format** is explicitly set to **CMake**.
4. Click **Generate IDE Project**.

---

## 💻 2. Visual Studio Code

1. Launch Visual Studio Code, select **File ➜ Open Folder...** and select the folder with the generated project.
2. An automatic auto-discovery process will run in the background, scanning your root directory files to identify the `CMakeLists.txt`.
3. When the alert notification pop-up asks: *"Configure discovered CMake project(s) as STM32Cube project(s)?"*, select **Yes**.

> 🛠️ **Troubleshooting Tips:**
> * If you miss this prompt or it disappears, click on the **Notification Bell icon** in the bottom-right corner of the status bar layout to retrieve it.
> * If you accidentally click *No*, navigate to the main menu bar options list and choose **STM32Cube ➞ Setup STM32Cube project(s)** to force the workspace indexing manually.
4. Select a configure preset for the project: `debug_GCC_STM32C562RET6` from the drop-down list.

### Inspecting Generated FreeRTOS Code
Navigate to `generated/middleware/mx_freertos_app.c` to examine the autogenerated code:
* Look at the top of the file to see the `function1` processing function prototype.
* Locate the task instantiation function blocks where the kernel memory stacks are registered.
* Scroll to the bottom of the file to view the empty placeholder code definition block for `function1`.

### Stitching FreeRTOS into Main Execution
By default, the autogenerated code defines the OS assets but does not automatically invoke them during the standard microcontroller boot loop. If you search all files using **CTRL + Shift + F** for `app_synctasks_init`, you will find it is not called. We must manually launch it.

1. Open `main.c` and include FreeRTOS app header file (~line 19):
```c
#include "mx_freertos_app.h"
```

2. Scroll down to the `main()` function execution path. 
Insert the following code just before the `while(1)` loop (~line 46)::

```c
    app_synctasks_init();   // Create FreeRTOS tasks and initialize resources 
    vTaskStartScheduler();  // Stark the FreeRTOS kernel
```

### Implementing the Thread Action
1. Open `mx_freertos_app.c` and scroll down to the infinite loop inside `function1`.
2. Add the code to toggle the LED and use the non-blocking delay function.

```c
static void function1(void *pvParameters)
{
  ( void ) pvParameters;

  for(;;)
  {
    HAL_GPIO_TogglePin(LED1_PORT, LED1_PIN);
    vTaskDelay(200);
  }
}
```

### Building & Debugging
1. Build your project using the status bar build button.
2. Open the **Run and Debug (CTRL + Shift + D)** view.
3. Click to `create a new launch.json` configuration file, and select **STM32Cube: Launch STLink GDB Server** from the context dropdown menu list.
4. Choose **STM32Cube: Launch STLink GDB Server** as your target.
5. Open your generated `launch.json` file and append **serverRTOS** somewhere into the main configuration block array:

```json
"preBuild": "${command:st-stm32-ide-debug-launch.build}",
"runEntry": "main",
"serverRtos": {
    "enabled": true,
    "port": "60000",
    "driver": "freertos"
}
```
> 💡 **Developer Note:** The integrated ST-Link GDB server architecture currently supports built-in thread-awareness drivers for `freertos` and `threadx`.
---
6. Click on **Start Debugging (F5)** to download the firmware directly into the physical target STM32C5 MCU and launch a debug session.
7. Click on **Continue (F5)** to resume execution, and observe the LED blinking within the RTOS thread.
8. Notice the new **STM32CUBE RTOS** tab appearing at the lower status bar panel.
9. Terminate the debug session by pressing **STOP (Shift + F5)**.

### Live Watch
1. Navigate to `mx_freertos_app.c` and declare a global variable at the top of the file within private variables section (line ~25).
```c
uint32_t Cnt = 0; 
```
2. Increment this variable in Task1.
```c
static void function1(void *pvParameters)
{
  ( void ) pvParameters;

  for(;;)
  {
    HAL_GPIO_TogglePin(LED1_PORT, LED1_PIN);
    Cnt++; 
    vTaskDelay(200); 
  }
}
```
### Building & Debugging
1. Build your project using the status bar build button.
2. Open the **Run and Debug (CTRL + Shift + D)** view.
3. Open `launch.json` file and append **liveWatch** somewhere into the main configuration block array:

```json
"liveWatch": {
    "enabled": true,
    "samplesPerSecond": "4"
}
```
6. Click on **Start Debugging (F5)** to download the firmware directly into the physical target STM32C5 MCU and launch a debug session.
7. Open **STM32CUBE LIVE WATCH** window on the bottom left, click on the plus symbol and add the `Cnt` variable. 
8. Click on **Continue (F5)** to resume execution, and observe the variable being dynamically incremented in real-time.
9. Terminate the debug session by pressing **STOP (Shift + F5)**.
